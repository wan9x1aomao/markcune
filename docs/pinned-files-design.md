# 置顶文件（常驻左侧）设计稿 v2 — 已实现

> 目标：日报、周报这类"每天都要开、但不在当前文件夹里"的文件，不必每次翻最近列表。
> 置顶后固定在左侧面板顶部，换文件夹也不消失。
>
> **v1 的"复制一份副本"已废弃**，原因见第 2 节。v2 的语义是**书签**：只记住位置，不复制文件。
> 实现见第 8 节。

## 1. 位置与信息架构

面板顶部一个**独立分组**，与"当前打开哪个文件夹"无关（现在的 `renderEmpty` 只在没有文件夹时才画最近列表，置顶不能挂在它下面）。

```
没有打开文件夹                 打开了文件夹
┌──────────────┐            ┌──────────────┐
│ 文件          │            │ 置顶   2   ＋ │  ← 固定，不随树滚动
│ 置顶   3   ＋ │            │ ───────────── │
│  📌 工作日报  │            │ 文件夹名  ＋⬇📁│
│  📌 周报模板  │            │  2026-03-20… │
│  📌 面试记录  │            │  草稿/        │
│  ＋ 置顶常用… │            │   素材说明.md │
│ ───────────── │            └──────────────┘
│ 打开文件夹…   │
│ 从链接打开…   │
│ 最近的文件夹  │
│ 最近的文件    │
└──────────────┘
```

- 顺序固定：**置顶 → 打开入口 → 最近的文件夹 → 最近的文件**（文件夹已打开时：置顶 → 文件夹标题 → 文件树）
- 置顶块**在滚动区之外**（`#sidebar` 里 `#sidebar-body` 之前的一个 `flex: none` 块），不是 sticky：长目录滚过去时它一格都不动，也不用猜背景色去盖住滚上来的行。最多 20 项，超出块内自己滚
- **空置顶整块不出现**：顶栏、首屏已经够满，一个永久占位的"＋ 置顶常用…"同理。入口放在 `···` 菜单「置顶此文件」和文件树的右键「置顶到常用」里
- 每行一行主标题 + 一行灰色路径（`~/Documents/工作/日报.md`，过长时省略中间）。路径是这里唯一能区分同名文件的信息

## 2. 为什么不做副本（v1 的问题）

v1 是「置顶时把文件复制进一个专用文件夹，之后编辑副本」。它有两处致命伤：

| 场景 | 复制副本（v1） | 书签（v2） |
|---|---|---|
| 编辑落在哪 | MDPad 里的副本 | 原文件本身 |
| **取消置顶** | 副本被删 → **你在副本里写的东西跟着消失** | 只删一条记录，文件原地不动 |
| 用别的编辑器改原文件 | 两份分叉，事后无法判断哪份新 | 不存在第二份 |
| 原文件被移动 / 别人发来新版本 | 副本还在，但已经不是"那份" | 行标灰，可重新定位 |
| 磁盘上多一份 | 是 | 否 |

一句话原则：**置顶只改变"在哪里能看到它"，不改变"它在哪里"。**

副本方案唯一站得住的场景是"原文件不能动"（只读目录、别人共享的模板）。那应该是**显式动作**，而不是置顶的默认行为——见第 6 节。

## 3. 存储：只存路径

`state.json` 增加：

```json
"pinnedFiles": [
  { "path": "/Users/ws/Documents/工作/日报.md", "addedAt": 1760000000000 }
]
```

- 只存绝对路径，**不新建文件夹、不复制文件、不改原文件**
- 显示名取文件名，不单独存（跟着磁盘上的真实名字走，避免"面板叫A、磁盘叫B"）
- 启动对账：`path` 不存在 → 标记 `missing`，**不自动删条目**（外置盘没挂、iCloud 未下载都会误判）
- 判重按路径；同一路径只允许一条
- 最多 20 个

## 4. 交互

**置顶入口（实际做了 3 个）**
- 当前文档 `···` 菜单 →「置顶此文件」（已在置顶则变成「取消置顶」）
- 文件树的右键菜单 →「置顶到常用」
- 置顶区的 `＋` → 从磁盘选文件（可多选；只在已经有置顶时才有这个块）
- 原计划的"最近文件行悬停出图钉"没做：20px 的悬停热区在触控板上一滑就走，收益不如两个菜单

**置顶时发生什么**
1. 读一次文件确认存在、是 md/txt
2. 加到置顶区顶部，立刻打开它
3. toast：「已置顶《日报》。以后打开的就是这份文件，在任何编辑器里的修改都是同一份。」（`settings.pinHintSeen` 控制只提示一次）

**取消置顶**
- 行内悬停 `✕`，**不弹确认框**（没有任何破坏性），直接移除
- toast 带上位置：「已取消置顶，文件还在 `~/Documents/工作/日报.md`」
- 若这份正是当前打开的文档：文档不关、不保存中断，只是顶部不再有那一行

**其他**
- 点击行 → 打开原文件；如果它不在当前文件夹里，**侧栏树不跟着切根**（不打断你正在浏览的目录），标题栏显示完整路径，避免"我在哪"的困惑
- 当前文档如果也在置顶里，该行高亮（和大纲里当前标题的处理一致）
- 右键菜单：打开 / 在 Finder 中显示 / 复制路径 / 重新定位…（仅 `missing` 时）/ 重命名 / 取消置顶
  - 重命名会**真的改磁盘文件名**，确认文案写明：「会改掉磁盘上的文件名，其他引用它的地方不受影响」
- 排序：按置顶先后固定，**不随使用变化**（要的就是位置稳定）；拖拽排序放第二版
- 置顶文件不出现在「最近的文件」里（按路径过滤，否则同一份在面板里出现两次）

## 5. 边界与异常

| 情况 | 处理 |
|---|---|
| 非文档（pdf/图片/文件夹） | 不给置顶入口 |
| 已置顶过同一份 | 不重复添加，直接高亮已有行 |
| 原文件被移动 / 改名 | 行标灰 +「重新定位…」；也可先在同目录按文件名找一次，找到就自动修好 |
| 原文件被删除 | 行标灰「文件已删除」，右键可移除；不自动清（网络盘、外置盘误判代价大） |
| 外置盘 / iCloud 未挂载 | 同上按不可用处理，不删条目 |
| 原文件在外部被改 | 打开时走现有的冲突检测（`check_document` + force），不另做同步 |
| 多窗口 | 置顶列表全局共享 |
| 超过 20 个 | 提示「置顶最多 20 个，先取消几个」 |

## 6. 什么时候才需要复制（第二版，先不做）

只有"原文件不能动"时才需要。届时做成**显式动作**，措辞是搬家而不是置顶：

- 右键「复制一份到 MDPad 文稿库…」→ 复制到 `~/Documents/MDPad/置顶/`，然后把这个**新路径**置顶
- 它和置顶是两件事，用户清楚知道自己多了一份

## 8. 落地时和稿子不一样的三处

1. **不做副本**（第 2 节）—— 取消置顶不会带走任何修改，这是用户提出的问题。
2. **空置顶不显示整块**（原稿写"留一行引导"）—— 与"首屏别堆按钮"同一个理由；发现路径改为菜单和右键。
3. **置顶块放在滚动区外，不用 sticky** —— 侧栏背景是渐变（`--panel-top` → `--panel-bottom`），sticky 要一块不透明底色去盖，接缝一定看得出来；`flex: none` 一个块既准确又不用调色。
